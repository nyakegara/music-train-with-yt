# Локальное определение BPM — дизайн

## Намерение

Автоматически подобрать BPM для текущей тренировки, не скачивая YouTube-видео и не передавая музыку сторонним сервисам.

## Подходы

1. **Анализ выбранного пользователем локального аудиофайла (выбран).** Пользователь открывает файл со своего компьютера; приложение декодирует его в памяти, вычисляет темп и сохраняет только принятое значение в настройках текущего видео. Это единственный из вариантов, который анализирует сам звук и не извлекает его из YouTube.
2. **Сторонний BPM Finder по YouTube-ссылке.** Указанный YouTube Toolkit описывает поиск числа BPM в названии, описании и тегах, оценку диапазона по жанровым словам и Tap Tempo; он прямо пишет, что не анализирует аудиоволну. Отправка ссылки третьей стороне добавляет передачу данных, а оценка диапазоном не заменяет аудиоанализ.
3. **Извлечение аудио из YouTube — отклонён.** Официальная политика YouTube запрещает клиенту включать скачивание видео или разделение аудиодорожек; сторонний downloader не меняет назначение функции.

Источник ограничения: [YouTube Developer Policies guide](https://developers.google.com/youtube/terms/developer-policies-guide). Описание предложенного сайта: [YouTube Toolkit BPM Finder](https://www.youtubetoolkit.com/tools/bpm-finder); страница говорит, что использует метаданные и Tap Tempo, а не анализ аудиоволны.

## Цели

- Кнопка «Определить BPM по файлу» открывает стандартный выбор локального аудиофайла.
- Анализ проходит полностью локально и не отправляет содержимое файла или ссылку на YouTube в сеть.
- Для защиты памяти принимаются моно и стерео аудиофайлы размером до 50 МБ и длительностью от 4 секунд до 5 минут; декодер сразу переводит их к 11,025 Гц.
- Результат с высокой уверенностью сразу становится BPM текущего видео; при неоднозначности пользователь подтверждает кандидата или выбирает half/double tempo.
- Принятое значение сохраняется существующим механизмом настроек по ID видео.
- Исходный файл не копируется, не загружается и не остаётся в кэше. После анализа ссылки на декодированный буфер освобождаются.
- «Первая доля» остаётся ручной: совпадение темпа не доказывает совпадение монтажа и временной фазы.
- Silence, слишком короткий файл, неподдерживаемый формат, повреждённые данные и низкая уверенность показывают понятные сообщения, не перезаписывая прежний BPM.

## Не входит

- Скачивание видео или извлечение аудио YouTube через сервис или библиотеку.
- Облачная обработка, загрузка аудиофайла, хранение waveform или временного MP3.
- Автоматическое совмещение первой доли с роликом YouTube.
- Отчёт о тренировке (отдельная задача #55).

## Детали реализации

- Чистый helper получает моно-сигнал и частоту дискретизации, строит огибающую атак и оценивает периодичность автокорреляцией в диапазоне 40–220 BPM.
- Результат содержит BPM, уверенность и альтернативные кандидаты около half/double tempo; для тишины, короткого и неритмичного материала возвращается `null`.
- Renderer использует Web Audio `decodeAudioData` для выбранного файла и очищает временные ссылки после завершения; файл не пишет в filesystem.
- В метрономе кнопка анализа располагается рядом с TAP; состояние анализа, ошибка, low-confidence подтверждение доступны через `role=status`/`role=alert`.
- После выбора кандидат сохраняется только числом `bpm` через существующий `update`, который уже пишет настройки в `practice:<videoId>`.

## Проверки

- Синтетические регулярные импульсы проверяют темпы 60, 90, 120 и 180 BPM.
- Отдельно проверяются половинный/двойной темп, тишина, низкий уровень шума, короткий сигнал, невалидные параметры и неожиданный отказ декодирования.
- UI проверяет выбор файла, автоматическое применение ясного результата, подтверждение неоднозначного, сохранение BPM только текущему видео и сохранение первой доли без изменений.
- Проверяется, что приложение не использует `fetch` для выбранного файла и не пишет исходный аудиобуфер в `localStorage`.
