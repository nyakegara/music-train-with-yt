# План: оценка начала устойчивого пульса из локального аудио

> Выполнять последовательно короткими циклами RED → GREEN → REFACTOR. Внешний звук и YouTube-видео не скачивать.

**Цель:** после локального анализа предложить пользователю начало наиболее уверенного устойчивого пульса, не меняя `firstBeat` без подтверждения.

**Архитектура:** чистый анализатор BPM расширяет свой результат отдельными полями фазы. Renderer хранит временный кандидат, привязанный к `videoId`, и применяет его существующей функцией `update` только по явному действию пользователя.

**Спецификация:** `docs/superpowers/specs/2026-11-08-local-pulse-phase-design.md`.

## Границы

- Использовать уточнённый период из выбранного лага, не округлённое значение BPM.
- `firstPulseSeconds` — начало наиболее уверенного устойчивого участка: наблюдаемый импульс с двумя соседними попаданиями. Это не downbeat и не начало сетки, спроецированное в тишину.
- `phaseConfidence` независима от BPM confidence; при плохой фазе показывать BPM, но не предлагать метку.
- Никогда не менять существующий `firstBeat` автоматически.
- Не хранить файл, метаданные, буфер или waveform; только пользовательски подтверждённый timestamp в настройках текущего видео.

## Проверка

- Unit: сдвиг и вступительная тишина, пропущенные первые импульсы, тихий импульс при контрасте 1:100, неоднозначное вступление перед чистым ритмом, нецелый темп на длинном сигнале, одиночный совпадающий transient и короткая поздняя последовательность.
- UI: подсказка привязана к видео; кнопка применяет только по запросу; анализ старого видео не меняет новое; отказ не сбрасывает метку; смена BPM не трогает метку.
- Запустить соответствующие Vitest файлы, полный `npm test`, `npm run build`, `git diff --check`; проверить UI превью и сделать скриншот.
